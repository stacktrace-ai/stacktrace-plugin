# 0.4.3 — Prompt injection Block, Codex native patches, and Cursor and Devin prompts

A Fleet Block entry for prompt injection now stops the call in Claude Code
before it runs. A detection rule set to Block also stops a Codex edit made
with the native `apply_patch` tool, before its file is written, and a Cursor
or Devin prompt.

## Highlights

- **Claude Code sends tool results for prompt injection** (stacktrace
  ADR-0223). New `PostToolUse` and `PostToolUseFailure` hooks send the result
  of an MCP, `Read`, `Grep`, `Glob`, `Bash`, `WebFetch`, `WebSearch`, `Agent`,
  `Task` or other reading tool to the local daemon. The daemon keeps only
  keyed hashes of the values that a result names, and only while the
  organization has a Block entry for `stacktrace-injection-followed`. A later
  call that carries a value only a planted instruction named is denied
  before it runs, and the agent asks the person. The hook never blocks and
  prints nothing.
- **Claude Code sends `Read`, `Grep` and `Glob` calls to the policy hook.**
  `stacktrace-secret-path-read` already reads their paths, but the plugin did
  not send them. A Block entry now stops such a call before it runs.
- **Codex sends native patches to the Stacktrace hook.** The Codex
  `PreToolUse` matcher adds `apply_patch`. A detection rule with a Block
  entry stops a patch that writes a credential, plants a start-up command or
  changes an agent's settings. Before, the edit was written and the scan
  found it after the fact.
- **Cursor and Devin send prompts to the Stacktrace hook.** Cursor's
  `beforeSubmitPrompt` and Devin's `UserPromptSubmit` run the policy hook. A
  blocked Cursor prompt gets `continue: false`, and Cursor shows the reason.
  A failed or older CLI adds no block.

## Install

Claude Code:

```text
/plugin marketplace add stacktrace-ai/stacktrace-plugin
/plugin install stacktrace@stacktrace
```

Existing installations update with `claude plugin update stacktrace@stacktrace`
or with marketplace auto-update. Restart Claude Code to apply the update.

Cursor CLI:

```text
agent plugin marketplace add github.com/stacktrace-ai/stacktrace-plugin --git-ref v0.4.3
```

Codex CLI: follow the "Codex CLI policy hooks" section of the README. After
the update, review the Stacktrace hooks in `/hooks`, or run the installer
again, which trusts the installed Stacktrace hooks.

Devin: follow the "Devin policy hooks" section of the README, with the tag
`v0.4.3`.

## Compatibility

- **Prompt injection Block needs `stacktrace-cli` 0.25.0 or newer.** An older
  CLI ignores the tool results, so the rule's Block denies nothing. Upgrade
  the CLI before this plugin, then restart the daemon.
- **Each `Read`, `Grep` and `Glob` call in Claude Code now starts the hook
  twice**, before and after the call. Each start runs the CLI once.
- Before Claude Code 2.1.319, ending the turn with `Ctrl+Enter` while a tool
  runs skips the post-tool hook, so that result is not marked.
- **Codex stops running the Stacktrace `PreToolUse` hook after the update
  until you trust it again.** Its matcher changed, so Codex reports the hook
  as modified, and it runs only trusted hooks. Until then, no Codex tool call
  is decided. Review the hooks in `/hooks`, or run the installer again.
- Requires `stacktrace-cli` 0.23.0 or newer for native patch blocking. An
  older CLI gives no decision, and the patch continues.
- Cursor prompt blocking needs `stacktrace-cli` 0.22.0 or newer.
- Devin prompt blocking needs `stacktrace-cli` 0.24.0 or newer. No signed-in
  Devin session has confirmed that Devin stops a prompt on a block.
- The other `stacktrace-cli` and Claude Code minimums are the same as in 0.4.2.
- **Native patch blocking is verified only from Codex code mode.** The tests
  use Codex 0.166.0, where the model calls `tools.apply_patch` from code
  mode. A direct `apply_patch` call outside code mode is not tested.
- **Each Codex native patch now runs the hook.** The CLI sends the patch text
  to the local daemon. That text does not go to Fleet. Only the finding of a
  block does.
