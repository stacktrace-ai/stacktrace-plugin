# 0.3.3 — Cursor and Codex policy hooks

## Highlights

- **Fleet policy in the Cursor CLI.** The plugin now installs in the Cursor
  CLI. Its `sessionStart` hook registers the project with the Stacktrace
  daemon. Its `beforeMCPExecution` hook asks the daemon about each MCP call.
  A call to a server that Fleet blocks is denied, and the denial names the
  Fleet rule. Cursor's own approval decides every other call. Cursor installs
  the plugin from a release tag (ADR-0011).
- **Fleet policy in the Codex CLI.** The plugin now carries Codex hooks.
  `SessionStart` registers the project, and `PreToolUse` asks the daemon about
  each MCP call. Codex runs the hooks only after you trust them in `/hooks`.
- **Coverage.** In Cursor and Codex, the hooks cover MCP tools, including the
  servers that a plugin bundles. They add no notification monitor and no
  skill admission. Claude Code coverage does not change.

## Install

Claude Code:

```text
/plugin marketplace add stacktrace-ai/stacktrace-plugin
/plugin install stacktrace@stacktrace
```

Existing installations update with `claude plugin update stacktrace@stacktrace`
or with marketplace auto-update. Restart Claude Code to apply the update.

Cursor CLI:

```text
agent plugin marketplace add github.com/stacktrace-ai/stacktrace-plugin --git-ref v0.3.3
```

Then run `agent` and type `/plugin`. Open the Marketplace tab, select
`stacktrace` and choose Install. To move to a later release, run the same
command with the new tag.

Codex CLI: follow the "Codex CLI policy hooks" section of the README.

## Compatibility

- Requires `stacktrace-cli` 0.5.2 or newer for Claude Code.
- Requires `stacktrace-cli` 0.17.0 or newer for the Cursor and Codex policy
  hooks. An older CLI rejects their commands, and the call continues with no
  policy decision.
- Requires Claude Code 2.1.274 or newer for policy admission hooks.
- The Cursor CLI `2026.10.22-27dcf5f` and Codex `0.163.0` are the tested
  versions. The Cursor and Codex desktop apps are not tested.
- The hooks, the monitor and the skills now look for `stacktrace` in an active
  virtualenv first, then in `~/.local/bin`, then on `PATH`.
