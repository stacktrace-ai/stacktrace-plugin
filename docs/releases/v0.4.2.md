# 0.4.2 — Codex shell commands and prompts reach Fleet policy

A detection rule set to Block now stops a Codex shell command and a Codex
prompt, as it does in Claude Code.

## Highlights

- **Codex sends shell commands to the Stacktrace hook.** The Codex
  `PreToolUse` matcher adds `Bash`, the name Codex gives its shell tool at the
  hook, also for a patch sent through the shell. A detection rule with a Block
  entry, such as credential egress, stops the command before it runs.
- **Codex sends prompts to the Stacktrace hook.** A new `UserPromptSubmit`
  handler runs the same command. A blocked prompt reaches no model.

## Install

Claude Code:

```text
/plugin marketplace add stacktrace-ai/stacktrace-plugin
/plugin install stacktrace@stacktrace
```

Existing installations update with `claude plugin update stacktrace@stacktrace`
or with marketplace auto-update. Restart Claude Code to apply the update.

Cursor CLI:

```text
agent plugin marketplace add github.com/stacktrace-ai/stacktrace-plugin --git-ref v0.4.2
```

Codex CLI: follow the "Codex CLI policy hooks" section of the README. After
the update, review the Stacktrace hooks in `/hooks`, or run the installer
again, which trusts the installed Stacktrace hooks.

Devin: follow the "Devin policy hooks" section of the README, with the tag
`v0.4.2`.

## Compatibility

- **Codex stops running the Stacktrace hooks after the update until you trust
  them again.** Codex 0.166.0 reports the updated `PreToolUse` and
  `SessionStart` hooks as modified and the new `UserPromptSubmit` hook as
  untrusted, and it runs only trusted hooks. Until then, no Codex call or
  prompt is decided, MCP calls included. Review the hooks in `/hooks`, or run
  the installer again.
- Requires `stacktrace-cli` 0.22.0 or newer for Codex shell command and prompt
  blocking. An older CLI gives no decision, and the command or the prompt
  continues.
- The other `stacktrace-cli` and Claude Code minimums are the same as in 0.4.1.
- **A native `apply_patch` call is not sent.** Its hook input is not yet seen.
  An edit made with it is found after the fact, not blocked.
- **Each Codex prompt now runs the hook.** The CLI sends the prompt text to
  the local daemon. That text does not go to Fleet. Only the finding of a
  block does.
