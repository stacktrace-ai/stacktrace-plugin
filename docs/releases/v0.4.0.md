# 0.4.0 — Policy hooks reach Codex CLI

## Highlights

- **Fleet policy applies to MCP tool use in Codex CLI.** The plugin now has a
  Codex manifest and Codex hooks. A Codex session registers with the user's
  daemon at the first user turn, not when the session opens. Each MCP tool
  call then asks the daemon for an admission decision, as a Claude Code call
  does. This covers MCP servers that a plugin is known to own. Plugin loading
  and skill context stay outside hook coverage. An older or missing CLI, or a
  daemon that does not answer, lets the call continue through Codex's own
  permissions.
- **The hooks and skills run the CLI of an active virtual environment.** When
  `VIRTUAL_ENV` is set and holds a `stacktrace` CLI, the hooks, the session
  start and the `status` and `findings` skills use that CLI. Otherwise they
  use `~/.local/bin/stacktrace` before an older copy on `PATH`. Before, a
  `~/.local/bin` copy could replace the virtual environment's CLI after a login
  shell changed `PATH`.
- **Bug fixes.** `/stacktrace:status` tells you to upgrade the CLI that the
  hooks actually run, not the first one on `PATH`.

## Install

```text
/plugin marketplace add stacktrace-ai/stacktrace-plugin
/plugin install stacktrace@stacktrace
```

Existing installations update with `claude plugin update stacktrace@stacktrace`
or with marketplace auto-update. Restart Claude Code to apply the update.

The Codex CLI adapter is a development adapter. The README section "Codex CLI
policy hooks" tells you how to test it from a local marketplace. Codex does
not trust the hooks until you review them in `/hooks`.

## Compatibility

- Requires `stacktrace-cli` 0.5.2 or newer.
- Requires Claude Code 2.1.274 or newer.
- Policy admission in Claude Code requires `stacktrace-cli` 0.13.0 or newer.
- Policy admission in Codex CLI requires `stacktrace-cli` 0.14.0 or newer.
  Codex 0.163.0 is the conformance reference. Codex desktop and cloud are not
  supported yet.
- A session started from a shell with an active virtual environment now uses
  that environment's `stacktrace` CLI, if it has one.
