# 0.5.1 — Codex sends tool results, so injection blocks work there

The Codex plugin now sends each MCP and shell result to Stacktrace. Then
Fleet's Block for an injected instruction stops a Codex agent before the call
that carries it out.

## Highlights

- **Codex tool results** (stacktrace ADR-0281). The Codex hooks file now has a
  `PostToolUse` entry for MCP tools and `Bash`, with the same command as the
  other Codex hooks. Each result goes to the daemon, as on Claude Code. Then
  `stacktrace-injection-followed` can block a later call that carries out an
  instruction from that result. Before, the daemon saw no Codex result, and
  the finding came only after the call. A native patch's result is only a
  status line, so it is not sent.
- **Cursor description.** The Cursor plugin's description now says what it
  checks: prompts, shell commands, file writes, deletes, reads and MCP calls.

## Install

Claude Code:

```text
/plugin marketplace add stacktrace-ai/stacktrace-plugin
/plugin install stacktrace@stacktrace
```

Existing installations update with `claude plugin update stacktrace@stacktrace`
or with marketplace auto-update. Restart Claude Code to apply the update.

Codex: `stacktrace setup` (CLI 0.29.0) installs or updates the plugin at the
released version and approves its hooks with each Codex. Without it, Codex
asks to approve the hooks again, because the hooks file changed.

Cursor CLI:

```text
agent plugin marketplace add github.com/stacktrace-ai/stacktrace-plugin --git-ref v0.5.1
```

## Compatibility

- **Codex results need `stacktrace-cli` 0.29.0** or newer. An older CLI reads
  the result and sends nothing, and the call that follows runs as before.
- The minimums for the rest of the plugin do not change: `stacktrace-cli`
  0.5.2 or newer, and Claude Code 2.1.274 or newer for the policy hooks.
